# 购物网站系统完整接口设计文档

## 1. 文档说明

本文档用于说明购物网站系统的接口设计，包括：

- 接口地址
- 请求方式
- 接口功能
- 是否需要登录
- 可访问角色
- 请求参数
- 返回结果
- 业务说明

系统角色分为两类：

- `USER`：普通用户
- `ADMIN`：管理员

---

## 2. 统一接口规范

### 2.1 接口前缀

- 用户端接口前缀：`/api`
- 管理端接口前缀：`/api/admin`

### 2.2 统一返回格式

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

### 2.3 状态码约定

- `200`：成功
- `400`：参数错误
- `401`：未登录或登录失效
- `403`：无权限访问
- `404`：数据不存在
- `409`：数据冲突
- `500`：系统异常

### 2.4 登录认证方式

系统采用 Token 认证机制。

- 登录成功后，后端返回 `token`
- 前端后续请求通过请求头携带 `token`
- 管理端和用户端的登录 token 分开校验

请求头示例：

```http
Authorization: Bearer xxxxxxxxxx
```

### 2.5 权限控制规则

| 角色 | 可访问范围 |
|---|---|
| 未登录用户 | 仅可访问公开接口 |
| 普通用户 | 可访问前台业务接口 |
| 管理员 | 可访问后台管理接口 |

特别说明：

- 普通用户不能访问 `/api/admin/**`
- 管理员不通过普通用户接口处理后台管理业务

| 模块 | 接口前缀 | 是否需要登录 | 可访问角色 |

## 4. 用户端接口设计

## 4.1 用户模块

### 4.1.1 用户注册

- 接口地址：`POST /api/user/register`
- 是否需要登录：否
- 可访问角色：未登录用户
- 功能说明：创建普通用户账号

请求参数：

```json
{
  "username": "zhangsan",
  "password": "123456",
  "nickname": "张三",
  "phone": "13800000000"
}
```

成功返回：

```json
{
  "code": 200,
  "message": "注册成功",
  "data": null
}
```

失败场景：

- 用户名已存在：`409`
- 手机号已存在：`409`
- 参数不完整：`400`

---

### 4.1.2 用户登录

- 接口地址：`POST /api/user/login`
- 是否需要登录：否
- 可访问角色：未登录用户
- 功能说明：普通用户登录系统

请求参数：

```json
{
  "username": "zhangsan",
  "password": "123456"
}
```

成功返回：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "jwt-token",
    "userInfo": {
      "id": 1,
      "username": "zhangsan",
      "nickname": "张三",
      "avatar": ""
    }
  }
}
```

失败场景：

- 用户名或密码错误：`401`
- 用户被禁用：`403`

---
